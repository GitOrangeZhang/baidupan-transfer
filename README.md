# baidupan-transfer

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

百度网盘分享批量转存工具：解决"单次转存文件数超限"的搬运难题——不是提高上限，而是**自动把超量内容拆成多批，逐批转存并校验落盘，同时保持原目录结构**。

> Batch-transfer large Baidu Pan (百度网盘) share links by automatically splitting them into multiple sub-limit batches. Works as an agent skill, or as a standalone packing utility.

> **声明**：本工具不提供任何绕过会员权益、解除下载限速或突破单次转存上限的功能。所有请求均由服务端强制校验账号权益；如需更大的单次转存额度，请升级账号会员。

---

## 它解决什么问题

百度网盘的转存上限按**账号权益**划分，与工具无关：

| 账号档位 | 单次转存文件数 |
|---|---|
| 非会员 | 500 |
| 会员（VIP / 工作 / 娱乐套餐） | 3000 |
| SVIP V1 | 50000 |
| SVIP V10 | 300000 |

当你保存一个内含数万文件的分享时，无论用手点还是用脚本，一次提交超过上限就会被拒（`errno: 12`）。

更坑的是：**分享页显示的「N 个文件」只是当前层级的条目数，不是文件总数**。页面写着「14 个文件」的目录，真实递归可能有几百上千个文件——靠肉眼永远算不准自己离上限还有多远。

本工具的做法：

1. 递归统计分享内每个目录的**真实文件数**；
2. 按上限的 80% 装箱（大项优先、整目录不拆开）；
3. 递归超过上限的目录逐层下钻，到子目录层再装箱；
4. 纯文件层（无子目录可拆）做文件级等分；
5. 逐批转存，`errno 12` 自动二分重试；
6. 全部完成后递归对账源与目标，逐层核对文件数。

## 特性

- **递归统计**：分页拉取目录树，得到真实文件总量
- **智能装箱**：整目录不拆散，减少批次数量与目录碎片
- **结构还原**：逐层容器法，在网盘侧预建同名目录，分批内容归位不错层
- **双转存引擎**：优先复用页面自身的转存接口（可精确指定目标路径），失败时回退到 UI 点击
- **断点续跑**：每批状态落盘，中断后只补未完成的批次
- **落盘校验**：`extra.list[].to` 与递归对账双重确认，确认零丢失
- **纯函数装箱器**：`pack.js` 无任何第三方依赖，可单独使用

## 安装

### 作为 Agent Skill 使用（推荐）

将整个目录放入你的 agent 技能的安装位置，例如：

```bash
git clone https://github.com/GitOrangeZhang/baidupan-transfer.git ~/.claude/skills/baidupan-transfer
# 或 TeleAgent / 其他支持 SKILL.md 约定的 agent：
#   放入其 skills 目录，重启客户端后在技能列表中选择本技能
```

目录结构：

```
baidupan-transfer/
├── SKILL.md           # 技能说明与完整执行流程（agent 读取）
├── scripts/
│   └── pack.js        # 装箱算法，零依赖，可单独调用
└── LICENSE
```

### 只使用装箱器

```bash
node scripts/pack.js '[{"name":"目录A","type":"dir","files":120},{"name":"目录B","type":"dir","files":260}]' --limit 400
```

输出人读摘要，并在 `__JSON__` 后附带机器可读结果：

```json
{"total":380,"limit":400,"batches":[{"files":380,"items":["目录B","目录A"]}],"needSplit":[]}
```

`needSplit` 表示该目录自身就超过上限，需要进入其中、对其子项重新装箱。

## 使用前提

- 需要一个能执行 JavaScript 的**浏览器自动化环境**（Playwright、Puppeteer、或浏览器 DevTools 控制台），并在已登录 `pan.baidu.com` 的页面上下文中运行脚本
- 登录只需用户本人在网盘 App 内扫码，工具不涉及账号密码
- 仅需 Node.js ≥ 14（用于 `pack.js`，无第三方依赖）

## 快速开始

1. **登录**：打开 `https://pan.baidu.com`，用户扫码
2. **统计**：打开分享链接（含 `?pwd=` 提取码），在页面上下文执行递归统计脚本，得到每项的 `files` 数
3. **装箱**：`node scripts/pack.js '<items JSON>' --limit 400`
4. **转存**：按批调用转存接口，`path` 参数指定目标目录（目标目录需事先存在）
5. **校验**：递归统计目标目录，与源逐层对账

完整的分步命令、选择器、参数模板与故障处理，见 **[SKILL.md](SKILL.md)**。

## 核心结论速查

| 问题 | 结论 |
|---|---|
| 页面显示的「N 个文件」能信吗 | 不能。那是当层条目数，需递归统计 |
| 装箱上限取多少 | 账号上限的 80%（非会员 500 → 用 400） |
| 为什么留 20% 余量 | 服务器计数会略高于本地统计（过滤项也计入） |
| 超限时返回什么 | `errno: 12`，响应含 `non_vip_limit` 与 `target_file_nums` |
| 大批量转存有什么特别 | 可能转异步模式，响应提示「文件转存中」，需延迟校验 |
| 重名会覆盖吗 | 不会，默认生成 `xxx(1)` 副本 |
